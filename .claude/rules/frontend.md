# Frontend (src/)

## Core Files

- **App.tsx** — Root React component: owns app-wide state, hook composition, playback/stream-resolver wiring, context menu, sidebar, and the view render tree. Views toggled via `View` union type: `"home" | "search" | "artists" | "albums" | "tags" | "history" | "collections" | "playlists" | "nowplaying" | "settings" | "extensions" | plugin:${string}`. The unified Library is `"search"` (rendered by `SearchView`); `"artists"`, `"albums"`, `"tags"` are detail-page views reached by selecting an entity from the Library. Simple confirmation/error/loading modals are presentational leaf components in `components/modals/` (`ConfirmModals.tsx`) — App.tsx owns their state and passes primitive props + callbacks; the components hold no app state. The native context-menu spec building lives in `contextMenu/buildContextMenuSpecs.tsx` — a pure `buildContextMenuSpecs(target, deps)` that returns the `MenuItemSpec[]` (or `null`) per `ContextMenuTarget` kind; App.tsx keeps a thin `buildAndShowNativeMenu` wrapper that owns `setContextMenu` + `showNativeMenu`.
- **App.css** — All styles. CSS Grid layout, CSS custom properties for skinning, 7-level type scale (`--fs-2xs` through `--fs-2xl`). Shared motion easing tokens (`--ease-out-quart` / `--ease-out-quint` / `--ease-out-expo`) live in `base.css`, alongside a global `prefers-reduced-motion` guard. Shared keyframe animations: `fade-in`, `scale-in`, `glow-pulse`, `slide-text-in`, `view-fade` (per-view crossfade), `row-in` (list rows).
- **skinUtils.ts** — Skin validation, CSS generation, customCSS sanitization.
- **telemetry.ts** — Anonymous usage analytics wrapper. `track(event, props?)` fire-and-forgets to the self-hosted Aptabase backend by invoking the `plugin:aptabase|track_event` Rust command directly (the `@aptabase/tauri` npm package is Tauri v1 and incompatible — do not add it). Gated by `setTelemetryEnabled(bool)`, which App.tsx mirrors from the `telemetryEnabled` store flag (default on / opt-out) on startup and on the Settings toggle. Props must stay anonymous (enum/count only — never titles, paths, or PII). See `deploy/aptabase/` and backend `telemetry.rs`.
- **utils/errorKind.ts** — `classifyErrorKind(error)` buckets any error into a **closed** enum (`network`, `timeout`, `not_found`, `permission`, `auth`, `rate_limit`, `server`, `format`, `disk_full`, `cancelled`, `dependency`, `parse`, `unknown`) so the *kind* of failure can ride along on telemetry without ever sending the message. Every error event carries `error_kind`; the classifier is unit-tested to never echo its input. Also exports `errorText(unknown)` for readable text (report buffer only — never telemetry).
- **utils/errorLog.ts** — Always-on in-memory ring buffer (50 entries) of uncaught frontend errors, fed by App.tsx's `window` error / `unhandledrejection` handlers. Exists because the backend log file is OFF by default, so for most users the errors worth reporting are written nowhere. Memory-only, never persisted, never transmitted. Inspect via `window.__appErrors`.
- **utils/diagnosticReport.ts** — Builds the "Report a problem" bundle: `buildDiagnosticReport(input)` (pure markdown formatter, unit-tested), `collectDiagnosticReport(sources)` (gathers backend facts via `collect_diagnostics` + track/collection counts), `scrubPaths()` (home dir → `~`, always applied), `issueUrl()`. **Nothing is transmitted from here** — the user reviews the report and copies it. That review step is why the bundle may carry log lines and library metadata that telemetry never could; see `telemetry.ts` for that separate, anonymous-only contract.
- **types.ts** — Core TypeScript types (Track, QueueTrack, Artist, Album, Tag, etc.). `Track` is the full library type with DB IDs; `QueueTrack` is the ID-less metadata type used by queue/playback/playlists.
- **types/skin.ts** — Skin system types (SkinJson, SkinInfo, SkinColors, GallerySkinEntry).
- **types/plugin.ts** — Plugin types (PluginManifest, PluginState, PluginContextMenuTarget, PluginViewData, ViboplrPluginAPI).
- **types/informationTypes.ts** — InfoEntity, InfoFetchResult, InfoTypeDeclaration, DisplayKind.
- **skins/** — Built-in skin JSON files (8 skins) and index.

- **WaveformSeekBar.tsx** — Waveform visualization via Web Audio API (RMS amplitude, max-RMS normalization). `useWaveform` computes a **width-independent** source peak array at one bucket per second (last bucket = remainder) and caches it as `{app_dir}/waveforms/{md5(key)}.json` where `key` is `v3::artist::title::duration` (bump the prefix when bucketing/normalization changes to invalidate old caches). `WaveformSeekBar` renders it by measuring its own canvas width and downsampling (average) to `min(peaks.length, maxBars)` bars, packing as many bars as fit without any *painted* bar dropping below `MIN_BAR_WIDTH_PX` (3px; `maxBars = floor(w·(1−BAR_GAP_RATIO) / MIN_BAR_WIDTH_PX)`, so the gap is accounted for). It re-fits via a `ResizeObserver` on the canvas (any layout-driven width change, not just window resizes), so the same cached array adapts to both the now-playing bar and the fullscreen bar. Draws a SoundCloud-style mirror (bright upper lobe + dim reflection below `AXIS_RATIO`).

- **FullscreenControls.tsx** — **The** fullscreen control bar, shared by both fullscreen surfaces: seek, art, like/dislike, title with artist/album links, transport, queue mode, auto-continue, **equalizer**, volume, subtitles, and — **only when the caller passes the callback** — queue toggle (`onToggleQueue`) and exit (`onToggleFullscreen`). The seek surface is the **same three-way ladder** as `NowPlayingBar` (`FilmstripSeekBar` → `WaveformSeekBar` → `SegmentedSeekBar`, then nothing when the duration is unknown), with the same `bufferedPct`, the same `BufferingChip` and the same hover bubble incl. the ± offset — see `ui.md` "Now Playing Bar". The EQ arrives as one `eq: EqControls` bundle rendered by the shared `EqControlGroup` (inline Bass/Treble slot **plus** the popover button — the group, not just the button); while its popover is open the bar **pins itself visible** (`handleEqOpenChange` → `eqOpenRef`, checked in `resetTimer`), because a 600px panel you read rather than drag would otherwise be yanked away by the 3s idle fade. Availability follows the bar's rule — audio always, video only under mpv (`nativeVideoActive`). In fullscreen this bar **is** the identity (the surface above it doesn't draw a title block), so `.fs-title` / `.fs-subtitle` scale with the display via **`--fsbar-title-size`** (`clamp(var(--fs-base), 0.9vh + 0.5vw, 28px)`, subtitle derived at 0.78), floored at the size they were fixed at. Safe to use viewport units here because `.fs-controls` only ever renders inside a fullscreen ancestor. Both stay optional, but only `onToggleQueue` is actually omitted anywhere: the audio surface's queue is edge-revealed, so that button would be a second route to a gesture that already exists. **Exit is passed on both paths** — the restore control belongs at the right end of the control bar in every fullscreen, matching where `NowPlayingBar` now puts its own fullscreen button (`.now-group--view`), so there is one corner to look in either bar. Gate new buttons the same way rather than adding a mode flag. App.tsx builds one `fullscreenControlsProps` object and renders it twice — inside `.video-container` and inside `AudioFullscreen` — overriding `onToggleFullscreen` (each surface exits itself) plus `active`, and on the audio path also `onToggleQueue: undefined`. Do not fork it: "the controls are the same in every fullscreen" is the contract, and two 40-prop call sites would drift on the first edit. The `active` prop declares "this is a live fullscreen even though there is no DOM `:fullscreen` element", and the idle auto-hide + cursor-hiding are gated on it. **Two** surfaces need it, both window-fullscreen: the audio overlay *and* native mpv video (`.video-container--native-fs`). Only the browser engine's video fullscreen is a real DOM `:fullscreen`. Miss it and the controls never hide — which is what happened on the mpv engine, the default.
- **NowPlayingView.tsx** — Lean-back current-track view, rendered in **two** places: the `nowplaying` main view and, via the `variant` prop, the fullscreen overlay (`AudioFullscreen`). Audio: blurred-art backdrop + album art + centered lyrics (no up-next panel — the Queue Panel owns upcoming tracks). Video: shared `<video>` repositioned to fill the column (theater mode, `.video-container--theater`) with a `VideoAmbientOverlay`. Lyrics via `useLyrics`, and collapsible: one `np-audio--nolyrics` flag covers both "this track has none" and "the user collapsed them" (persisted as `nowPlayingLyricsHidden`, **shared by both variants** so the two surfaces always agree), and a visualizer in the art column grows to take the freed stage. The lyrics column is **unmounted** when collapsed, not hidden — the synced panel runs a position-driven auto-scroll that would keep ticking behind `display: none`. Slot sizing goes through the `--np-vis-size` custom property, art sizing through **`--np-art-size`**, lyric type through **`--np-lyric-size`** and the identity block through **`--np-title-size`** (subtitle and tags are `calc()`-derived from it at 0.53 / 0.44 so the three lines can't fall out of proportion) — rather than per-case rules: with four combinations (lyrics on/off × variant) and *two* readers for the art size (`.np-art` plus the `.np-xfade--art` frame around it), plain width/height rules mean eight declarations that must agree, and the two-class `--nolyrics`/`--fs` selectors out-specify anything scoped narrower (it already silently handed small windows the large visualizer). Art resolution is the pure `utils/nowPlayingArt.ts` → `resolveNowPlayingArt` (unit-tested), which reports **`pending`** as well as the path: art decides the whole surface regime (blurred backdrop + always-light `--hero-text-*` vs `--noart` skin gradient + skin text), so an in-flight lookup read as "no art" committed to the wrong regime and inverted every line of text a frame later on a light skin. While `pending`, the view holds the art regime over the `--np-backdrop-base` dark layer (`base.css` — the light text needs a dark base before there is anything to blur) and the art column shows an empty frame rather than the initials fallback. App.tsx also uses `resolveNowPlayingArt` for `nowPlayingArtSrc` (the visualizer host's `currentArtUrl`), ignoring `pending` — that consumer only shows an image late, it doesn't switch a regime on the answer. See `ui.md` "Now Playing View".
  - **`variant`:** `"view"` (default) draws the title/artist/album line and the tags line; `"fullscreen"` suppresses both — `FullscreenControls` underneath already carries the title with clickable artist/album links, so drawing them again is the same fact twice on one screen — and skips the tags `find_track_by_metadata` → `get_tags_for_track` round-trips entirely. It also adds `now-playing-view--fs`, whose only job is sizing: with the caption bar, sidebar, now-playing bar and title block all gone, every budget the in-grid tier reserves for them is wrong, and `--np-vis-chrome` left at its in-grid `300px` would make a *fullscreen* visualizer come out **smaller** than the windowed one. The `.np-actions` row travels over **whole** — same three buttons, same order; `onToggleFullscreen` is one callback for both directions and only the glyph flips (arrows out → arrows in, matching `FullscreenControls`' own exit). A row that dropped an item on the way in would lose the very button the user just pressed. It needs **no** fullscreen sizing/opacity tier: the row auto-hides on an idle timer (`useIdleVisibility`) in both variants, which replaced a hover-floor that had to be overridden here because `:hover` on a fullscreen view is permanently true.

- **DownloadModal.tsx** — Unified download flow (provider-chain resolution, interactive manual search, progress). See conventions.md "Download Track". The resolve step is not always a quick URL lookup — a provider that downloads the file itself runs for minutes there — so `SingleTrackDownload` keeps **Cancel live** during it (wired to `onCancelResolve` → `plugins.cancelDownloadResolve`, which kills the provider's subprocess), guards late results with a generation ref, and renders whatever the provider reports through `api.downloads.reportProgress` (bar when `percent` is known, spinner otherwise, elapsed counter always).

- **BufferingChip.tsx** — "Buffering…" indicator for a stalled network stream, shared by `NowPlayingBar` and `FullscreenControls`. Renders **absolutely, over** the seek track (both hosts are `position: relative`) rather than taking layout — a chip that reflows would shove the waveform sideways on every hiccup, and a bar that jumps when the stream stutters is worse than no indicator. Deliberately not a toast: toasts dismiss after 4.5s and a stall can outlast that (same reasoning as the queue's backfill row). The number is **seconds of audio recovered** (`formatReadahead`), not a percentage — a percentage sat at a static 0 through real stalls; readahead climbs, which is what answers "is this recovering?". Degrades to the bare word when no engine supplied a figure.
- **SegmentedSeekBar.tsx** — Segmented (non-waveform) seek bar variant for the Now Playing bar (shown when no waveform exists, e.g. remote/subsonic tracks). Blocks are laid out **proportional to time** — one per second, or per minute when seconds pack below `MIN_SEG_WIDTH` (3px) — so a block's left edge lands on that exact second/minute mark under the linear seek-click map, and the final block is the leftover remainder (narrower). Uses the same `AXIS_RATIO` mirror (bright upper lobe + dim reflection) as `WaveformSeekBar` so the fallback reads consistently.
- **AutoContinuePopover.tsx, EqPopover.tsx** — Popover controls for auto-continue strategy weights and the equalizer.
- **TransportControls.tsx / SeekSurface.tsx** — The controls **both** playback bars render, extracted so they cannot drift. `TransportControls` exports `TransportButtons` (prev · play/pause · next · stop), `QueueModeGroup` (queue mode · auto-continue, owning its own popover anchor ref; Randomize moved to the queue panel header) and `VolumeControl`. `SeekSurface` exports `SeekLadder` (which of `FilmstripSeekBar` / `WaveformSeekBar` / `SegmentedSeekBar` a track gets — **the** answer, not one per bar), `SeekHoverBubble` (scrub time + the ± offset + storyboard tile) and `seekHoverAt` (pointer → `{pct, x}`, measured against the *wrapper* because the track clips).
  - **Why extracted:** these were verbatim copies in both files, which is exactly how the fullscreen bar ended up with no equalizer, no segmented seek bar and no ± offset. Each export takes the host's container class (`.now-controls`/`.fs-center`, `.now-volume`/`.fs-volume`, `now-seek-bubble`/`fs-seek-bubble`) because the layout *around* them genuinely differs — nothing else about them may. New shared controls go here; a control that belongs to only one bar stays in that bar.
  - **Why the bars still can't be one component:** the fullscreen bar must be a child of whatever element got `requestFullscreen()` (the browser renders only that subtree — hence `.fs-controls { display: none }` by default, switched on by `.video-container:fullscreen` and `.audio-fs`), and it carries an idle auto-hide plus a colour regime for sitting over arbitrary video frames. The docked bar additionally owns the whole mini player, the source tooltip, tags, download, ICY title and error states. See `ui.md` "Now Playing Bar".
- **LyricsOffsetControl.tsx** — Per-track synced-lyrics timing nudge (`[«] ±Ns [»]`, 0.5s steps / Shift 5s / click-readout-to-reset), mounted by `NowPlayingView` (synced lyrics only) and `VideoAmbientOverlay` (only while subtitles are on). The maths lives in `utils/lyrics.ts` — **`lyricPosition`** (positive delays; owns the sign for all four consumers), `clampLyricOffset`, `formatLyricOffset`, `lyricOffsetKey` — all unit-tested. App owns the persisted `lyricsOffsets` record. See `ui.md` "Now Playing View" → Lyrics timing offset.
- **SourceIndicator.tsx** — "Where is this actually coming from?": the small icon on a playback bar's subtitle line plus its hover panel (source label, live decode facts, path/URL, Open folder / Open on *X*). Owns its own `audioProps` fetch (lofty) and the on-hover `nativeEngine.getMediaInfo()` call (the **only** quality source for streamed audio and all video). The chain feeds it: `attributedSourceUrl` (`useStreamResolution.ts`, pure + tested) keeps a resolver's reported `sourceUrl` but, when it reported none and the resolution landed on a **file**, derives `file://<engineSource.path>` — so a plugin scheme that plays a local file is attributed to that file with no cooperation from the plugin, which matters because a plugin's own reporting is version-gated and an older build has nothing to read. **What the panel probes is `effectiveLocalPath(track, resolvedSource)` (`queueEntry.ts`), not the track's own scheme** — one helper shared with the path row, so the decode facts and "Open folder" can't disagree about whether there is a file. Gating on `isLocalTrack` alone read the *scheme*, so a plugin-scheme track playing a file sitting right here (qbt://…) got no lofty properties and fell back to the engine, which knows the sample rate but not the file's bit depth: a 24/96 FLAC read "FLAC · 96.0 kHz" with the 24-bit missing. Mounted by **both** bars — it used to be inlined in `NowPlayingBar` only, so the answer vanished exactly when the user went fullscreen. It is **self-contained on purpose**, and that is load-bearing: the panel is `position: fixed` so it *could* be hoisted, but inside DOM `:fullscreen` the browser paints only the fullscreened subtree, so a panel rendered at the app root would silently never appear over fullscreen video. Keep it next to its icon. Over video the icon takes `color: inherit` (`.fs-subtitle .now-source-icon`) instead of its skin grey.
  - **The `source` row and the "Open on *X*" button are entirely generic** — they render whatever the winning chain entry reported as `ResolvedSource.sourceUrl`, and the button appears whenever that is `http(s)`. The component knows nothing about individual plugins and must not learn: a plugin names its own page by *reporting* `sourceUrl`, from either resolver (`onStreamResolve`, or `onResolveStreamByUri` alongside `candidates` — see `plugins.md`). A track played from its own plugin scheme whose resolver reports nothing falls back to the raw URI, which for an encoded scheme (`ytdlp://https%3A%2F%2F…`) is unreadable and un-openable — that is a missing report, not something to special-case here.
- **EqButton.tsx** — The equalizer cluster, shared by `NowPlayingBar` and `FullscreenControls`. ## Hooks (src/hooks/)

- **useLatestRef.ts** — The two primitives for the "latest ref" pattern, which this codebase leans on everywhere: a ref holding the newest value/closure so async consumers (event handlers, timers, mpv/Tauri listeners, plugin callbacks) read it without being re-subscribed each render. **`useLatestRef(value)`** creates and feeds a ref; **`useAssignRef(ref, value)`** writes into a ref that already exists — the forward-declaration case that dominates `App.tsx`, where a ref is handed to `usePlayback` near the top and only filled in hundreds of lines later once the handler it points at is defined. Both write inside **`useInsertionEffect`**, and that specific effect is load-bearing: insertion effects for the whole tree complete during the mutation phase, *before* any `useLayoutEffect` or `useEffect` anywhere, whereas layout/passive effects run child-before-parent — so a parent writing in one of those would publish the value *after* a child's effect had read the stale one. Same mechanism as React's own `useEffectEvent` polyfill. The write is deliberately dependency-free (one assignment per commit, no dep list to get wrong).
  - **Never write a ref in a render body.** `xRef.current = value` as a statement of a component/hook body is a render-phase write: StrictMode double-renders and concurrent rendering can start and discard a render, mutating the ref for a tree that never commits. 100 such sites were converted to these hooks; `eslint.config.js` gates the pattern as an **error** via a `no-restricted-syntax` selector (a direct `.current` assignment in a component/hook block), so it cannot come back. Writes inside effects, callbacks, conditionals and loops are unaffected and legal.
  - **This does not make refs render-safe to read.** Reading `.current` during render still yields the previous commit's value. Use state for anything render output depends on.
  - **Exceptions that are deliberately not this pattern:** `VisualizerSlot`'s `queueRevision` counter bumps in an explicit `useInsertionEffect` (its only reader is the rAF frame loop, always post-commit), and `pluginViews`' text input resyncs from a prop using React's documented *previous-value-in-state* form rather than a ref.
- **useStableCallbacks.ts** — Gives every function in a `handlers` object a render-stable identity that dispatches to the latest closure, so a `memo`ized child (`NowPlayingBar`) can take inline handlers from App.tsx without defeating its memo. Built on `useLatestRef`; the key set is fixed by the first render and captured in a lazy `useState` initializer (**not** read off `ref.current` inside the `useMemo` — a `useMemo` body runs during render, so that would be a render-phase ref read).
- **usePlayback.ts** — Dual A/B audio element architecture for gapless/crossfade. Crossfade via setInterval volume ramp. Video tracks don't crossfade. `currentTrack` is `QueueTrack | null`. Also owns the **native mpv session branches**: when the full build's engine is selected (`useNativeEngineRef`), eligible audio routes through `src/playback/nativeEngine.ts` instead of the elements — `nativeSessionRef` marks the session, `engine-*` events stand in for element events, and any `engine-error` blocklists the key + replays the same track at the same position on the browser engine (per-track fallback). The scrobble/preload/crossfade decision logic is extracted to `src/playback/progressMachine.ts` (pure, unit-tested) and driven by BOTH `timeupdate` and `engine-position`. Also owns **`playbackRate`** (exposed as `playbackRate` / `setPlaybackRate`), applied to both audio elements *and* the preloaded one *and* mirrored to mpv — an element left at 1.0 would snap back to normal at the gapless hand-off. `applyRateTo()` sets `preservesPitch = false` (and the webkit-prefixed name), which is the one line that makes this a deck rather than a speed-reader: pitch follows tempo, as a turntable resamples. Deliberately **not persisted** — a rate silently restored at 1.35x reads as "my library got transposed", so every launch starts at 1x. Also owns **`buffer`** (`PlaybackBuffer | null`, see `src/playback/bufferState.ts`): fed by the `engine-buffer` subscription on the native path and by `onMediaProgress` / `onMediaWaiting` / `onMediaPlaying` (wired onto both `<audio>` elements and the `<video>` in App.tsx) on the browser path. Two rules keep the engines saying the same thing: the browser buffered-range read is skipped for `isLocalTrack` sources (matching the engine's `demuxer-via-network` gate), and stall detection is armed only after the first `playing` event (`browserPlaybackStartedRef`) — a media element fires `waiting` during its *initial* load and mpv's `paused-for-cache` does not, so without the gate every browser-engine track start would flash "Buffering…" at an ordinary load. `clearStreamReadouts()` resets `icyTitle` + `buffer` + that ref together at every session boundary (explicit play, stop, gapless hand-off, engine track change, engine error) — one call site per boundary, not one per readout.
- **src/playback/nativeEngine.ts** — Typed invoke/listen bridge to the mpv engine (`engine_*` commands, `engine-*` events). Capability probed via `engine_capabilities` and cached; `refreshEngineCapabilities()` drops the cache and re-probes (used after an engine-component install — backend load failures aren't cached, so a fresh install unlocks live, no restart). All control methods no-op when incapable. EQ/ReplayGain/**speed** settings are mirrored to it from usePlayback's existing effects (cached backend-side until the engine runs). `setSpeed` maps to mpv's `speed` on BOTH decks — the idle one is what gapless preloads into. mpv's `audio-pitch-correction` is turned **off** at init so speed shifts pitch too.
- **src/playback/bufferState.ts** — `PlaybackBuffer` (`stalled` / `readaheadSecs` / `bufferedToSecs`) plus the pure `bufferedEndAt` / `bufferedFraction` / `formatReadahead` / `applyBuffer`. Where the two engines' buffer reporting is normalized: mpv sends the `engine-buffer` event, and the browser engine yields the same two numbers from `HTMLMediaElement.buffered` — the covering range's end is the buffered edge, `end - currentTime` is the readahead — plus `waiting`/`playing` for the stall flag. There is deliberately **no refill percentage** (see backend.md: mpv's reads a near-constant 0 through a real stall). **`null` means unknown, not empty** — most local files report nothing, and rendering that as "0% buffered" would dim the whole seek bar for a file already on disk; every consumer treats null as "draw no buffered edge". `bufferedEndAt` returns only the range *covering* the play position: data past a gap can't be played through, so drawing out to it would promise a smooth ride the element can't deliver. **`bufferedFraction` snaps to 1 within `FULL_SLACK_SECS` (2s) of the duration** — a fully cached stream never reports its edge *at* the duration (mpv's `demuxer-cache-time` is the last packet's timestamp; measured ~59.98 for a 60.0s file by the engine's `probe_buffered_edge_vs_duration`), and the seek bars count a block straddling the edge as unbuffered, so without the snap the final block of every fully-downloaded remote track stayed dim forever. `applyBuffer` returns the previous object identity when nothing moved, because the browser `progress` handler fires several times a second and a fresh object each time re-renders the whole now-playing bar for no visible change.
- **src/playback/progressMachine.ts** — `driveProgressMachine()`: given position/duration/arming state, decides prefetch / preload (20s lead, 45s when the next track needs stream resolution) / crossfade-start. Single source of truth for both engines. **Every threshold is in track seconds but budgets wall-clock time**, so they are all scaled by `rate` — at 1.35x an unscaled 45s stream-resolve lead is only 33 real seconds, quietly eating a quarter of the window yt-dlp was given, and the failure looks like a gap between tracks rather than a rate bug.

Measured against real libmpv by `probe_engine_audio_params` (`mpv_engine/mod.rs`, `#[ignore]`d, recipe in its doc comment). For a file on disk the `builtin:quality` item therefore prefers lofty (`get_audio_properties_by_path`) over the engine; video stays engine-only (resolution), and streams have no other source. Exports pure helpers `isNowPlayingItemSelected` / `formatPlays` / `formatSource` / `formatQuality` / `formatTags` / `nextCycleIndex` / `nowPlayingOrderedItems` / `setNowPlayingItemPriority` / `nowPlayingMenuLabel` (unit-tested); lyrics line helpers live in `utils/lyrics.ts`. Selection / ToP / order persisted by App.tsx as `nowPlayingInfoSelection` / `nowPlayingInfoPersistence` / `nowPlayingInfoOrder`.
- **useEntityDetail.ts** — Loads detail-page data (tracks/albums/sections) for a selected artist/album/tag.
- **useDetailHeroImages.ts** — Resolves the multi-image background set for `DetailHero`.
- **useArtistInfo.ts** — Artist metadata loading for the artist detail page.
- **usePlayActions.ts** — Shared play/enqueue action helpers routed through the canonical queue actions. Also owns `playWithBackfill` (play a known head now, append the async remainder — generation-guarded via `useQueue.appendToPlaySession`, head de-duped by the exported pure `dropPlayedHead`) and `startRadio` (which enriches the banner cover after playback starts). See conventions.md "Play With Backfill".
- **useCollectionActions.ts** — Collection CRUD/resync action handlers for `CollectionsView`.
- **useExtensions.ts** — Extension/plugin install, enable/disable, update checking for `ExtensionsView`. Three rules the "Update All" freeze came from, all load-bearing: (1) the `extension-update-installed` listener re-checks **only** for installs it didn't initiate (`selfInitiatedRef`) — re-checking per install made a batch quadratic, since each check is itself N network round-trips; (2) `performUpdate(id, { deferReload })` — a plugin reload rebuilds the *entire* plugin runtime, so a batch defers it and calls `onReloadAllPlugins()` **once** at the end; (3) reloads are **awaited** (`onReloadPlugin` returns `void | Promise<void>`) — fire-and-forget let N rebuilds overlap. `progress` (keyed by id, fed by `plugin-install-progress`) drives the byte readout in `PluginLoadingModal`. Failures that were `console.error`-only — uninstall, enable/disable, install-from-URL — now also reach the user via `onNotify` / the result modal.
- **useDependencies.ts** — External-binary dependency state (install/update/progress/check). See `backend.md` "External Binary Dependencies". The **`dependency-updated`** listener (the background auto-updater's completion event) must **re-probe** the row, never remove it: it used to `setDeps(prev => prev.filter(...))` on the theory that "the next look re-probes", but nothing performs that next look — `SettingsPanel`'s mount effect is gated on `deps.length === 0` and ffmpeg keeps the list non-empty — so a silently updated yt-dlp *disappeared* from Settings → Dependencies until the user hit Refresh. The re-probe is **guarded on the row already being present**, because the updater fires 30s after launch, typically before any check has run: probing unconditionally would *create* a one-row `deps` and that same `length === 0` gate would then skip the full `checkAll`, showing yt-dlp and no ffmpeg. Both callbacks reach the listener through `useAssignRef` forward refs (they're defined below it) — see **useLatestRef.ts**.
- **useEngineComponent.ts** — Install state + actions for the downloadable libmpv engine component (Settings > Playback): status, streamed `engine-component-progress`, install/uninstall invokes, and a `refreshEngineCapabilities()` re-probe on completion. See `backend.md` "Native mpv Engine".
- **useVideoFrames.ts** — Video frame thumbnail caching/extraction bridge (`video_frames.rs`).
- **useStoryboard.ts** — Seek-preview storyboard for one video track: plugin scheme → the owning plugin's published sheet, `file://` → cache read then one local ffmpeg pass (`storyboard.rs`). The `enabled` argument is Settings → Playback → "Video seek previews" and gates **only** the local pass — cached and source-published sheets are still served (`status: "off"` means "nothing cached and nothing decoded"). Its effect cleanup **cancels a pass in flight** (`cancel_storyboard`) on a track change, unmount, or the setting going off, so a full keyframe decode never outlives the video the user was on; interest is ref counted backend-side, so the now-playing bar and the detail page can want the same sheet without either teardown killing it. A cancelled pass is **resumed** next time rather than restarted, which is why `PartialStoryboard` carries `startIndex`: a resumed pass extracts the tail of the video, so its frames start mid-way and reading them positionally would caption every one with the wrong timestamp. See `docs/seek-preview-spec.md`.
- **useMiniSearch.ts** — Mini-mode quick-search state for `MiniSearchPanel`.

## Keyboard Shortcuts

No modifier (when not in text input): Space (play/pause), arrows (seek/volume).
Cmd/Ctrl: 0 (Home), 1 (Library), 2 (History), 3 (Now Playing), K (search), F (fullscreen), L (like), P (playlist panel), M (mute), Shift+M (mini), B (sidebar), Left/Right (prev/next track).
**Cmd/Ctrl+F** dispatches by track kind: video → the video/native-mpv fullscreen path; audio → the `AudioFullscreen` overlay. The two never contend for the key. That dispatch lives in **one** place — App's `toggleFullscreenForTrack` (gated by `canFullscreen`) — which the shortcut hook and the now-playing bar's fullscreen button both call. Do not re-derive the video/audio branch at a new call site.
Track list: a focusable ARIA listbox (`TrackList` — `role="listbox"`/`"option"` + `aria-activedescendant`). Tab to focus the list, then arrows / Home / End move the cursor (Shift+arrow extends selection), Space toggles selection, Enter plays, Shift+Enter enqueues. Cmd/Ctrl+A selects all, Delete removes (local), Escape clears selection.
Mini mode: any printable character (when no input is focused) opens the mini-player quick-search panel; Space/arrows remain player controls.

## State Persistence

UI state persisted via `tauri-plugin-store` to `app-state.json` in profile directory. Key states: current track + position, queue (track IDs + index + mode), volume, window geometry (full + mini separately), crossfade, auto-continue weights, view modes per entity, Extensions plugins layout (`pluginViewMode`: `"cards"` | `"list"`), per-contribution plugin visibility (`pluginContributionVisibility`), skin, sort/filter per entity, section toggles, Now Playing info selection / dwell / order (`nowPlayingInfoSelection`, `nowPlayingInfoPersistence`, `nowPlayingInfoOrder`), Now Playing lyrics collapsed (`nowPlayingLyricsHidden`), per-track lyrics timing offsets (`lyricsOffsets`, keyed by `lyricOffsetKey`; zero entries are pruned), local video seek-preview generation (`videoStoryboards`, default on), onboarding profile (`onboardingProfile`), anonymous-telemetry opt-out (`telemetryEnabled`, default on) + one-time install-reported guard (`telemetryInstallReported`). (Last.fm session/auto-import state lives in plugin storage, owned by the lastfm plugin — not the app store.) Saves debounced at 500ms. A `restoredRef` guard prevents overwriting persisted data with defaults on startup. On mount, App.tsx's restore effect reads the primary settings via `startup/readPersistedSettings.ts` (`readPersistedSettings(store)` returns a named object — no positional tuple) and then applies them to its hooks/setters. `view` and selected-entity state are intentionally NOT read/restored — startup always lands on Home.

## Scrobble Threshold

Play history / Last.fm scrobble recorded after 50% of duration or 4 minutes (whichever first). Tracks < 30 seconds are never recorded. Video tracks excluded unless "Track video history" is enabled.
